# RideHUD Web v0.3 — GitHub Pages 버전

**Garmin FIT → 자유 배치 계기판 → 브라우저에서 60fps WebM 또는 투명 PNG 시퀀스 출력**

## 설치 없이 웹에서 열기 (GitHub Pages)

1. GitHub 계정으로 새 저장소(repository)를 만듭니다. 예: `ridehud-web`. Public으로 만듭니다.
2. 이 압축파일 안의 **index.html, style.css, js/ 폴더, examples/ 폴더를 저장소 루트에 업로드**합니다. 압축 파일 자체를 GitHub에 올리면 사이트가 동작하지 않습니다.
3. `Settings → Pages → Build and deployment → Deploy from a branch`에서 `main` / `/(root)`를 선택하고 Save.
4. 게시가 완료되면 `https://사용자명.github.io/ridehud-web/`로 접속할 수 있습니다. GitHub 계정에 따라 게시가 반영되기까지 시간이 걸릴 수 있습니다.

GitHub Pages는 정적 사이트 호스팅만 담당합니다. 영상 생성용 별도 서버/비용/계정 연결은 필요하지 않습니다. FIT는 사용자 브라우저 안에서만 분석되며 서버에 업로드하지 않습니다.

## 계기판 사용

1. `*.fit` Garmin 활동 파일을 드래그하거나 `샘플 FIT으로 체험하기` 클릭.
2. 왼쪽에서 데이터 항목을 추가. 미리보기에서 카드 **드래그 이동**, 오른쪽 아래 파란 핸들 **크기 조절**.
3. 카드 선택 시 항목 변경, 색상 변경, 삭제 가능. 레이아웃 JSON 저장/불러오기.
4. FIT 시작 시점부터의 경과시간으로 **시작/종료** 설정 (예: `00:11:30`~`00:12:00`).
5. 파일 포맷을 고르고 **영상 내보내기**.

18개 항목: 현재/평균/최고속도, 3초파워/평균파워/NP, 현재/최고/평균케이던스, 현재/최고/평균심박, 구간거리/총거리, 경과시간/현재시간, 현재경사도/누적 상승고도.

**평균·최고·NP는 영상 구간만의 통계가 아니라 처음부터 해당 재생 시각까지의 누적 통계입니다.** 3초 파워도 해당 시각 이전 3초를 평균합니다. FIT 간격이 벌어지는 구간에서는 데이터를 임의 생성하지 않습니다. 평균속도는 이동 속도 샘플을 기준으로 계산되어 가민 요약과 다소 다를 수 있습니다. NP는 직전 30초 평균 파워의 4제곱 누적 평균으로 계산하며, 기록 공백/정지 처리 규칙 때문에 Garmin Connect 수치와 차이날 수 있습니다. GPS 표준 기록값을 사용합니다. 현재시간은 브라우저 PC의 시간대 설정을 사용합니다. 경사도는 기록이 있으면 사용하고 아니면 거리/고도로 추정합니다. 획고는 고도 변동을 평활화하여 누적하므로 Garmin 요약값과 다를 수 있습니다.

## 출력 방식 선택

| 출력 | 장점 | 제약 |
|---|---|---|
| **WebM 60fps (투명 시도)** | 1개 영상 파일, 별도 설치 없음 | 브라우저 MediaRecorder가 알파 채널을 지우거나 편집기가 무시할 수 있음. **투명 보장 불가**. 요청 60fps이나 실시간 캡처 프레임 누락 가능 |
| **WebM 60fps (초록 배경)** | 일반 영상으로 생성되고 색상 키 제거 가능 | 편집기에서 크로마키(녹색 제거) 필요, 녹색 요소가 있다면 같이 제거됨 |
| **투명 PNG 시퀀스 ZIP (권장)** | RGBA 알파 확실, *정확히 60fps 프레임 수* 생성, 컷 합성 적합 | 파일 크기와 렌더링 시간 큼. 편집기에서 이미지 시퀀스로 불러와 60fps 지정해야 함 |

WebM은 PNG보다 손쉽지만 프로그램/코덱 조합에 따라 투명도를 보장할 수 없습니다. **투명도가 최우선이면 PNG 시퀀스를 사용하세요.** MOV ProRes 4444는 브라우저에서 직접 인코딩하지 않습니다. 필요하다면 사용자가 PC의 FFmpeg 등으로 PNG 시퀀스를 ProRes 4444 MOV로 변환할 수 있습니다.

### 파일 크기/성능
- 해상도: 1920×1080 / 3840×2160. 출력 60fps.
- WebM: 실시간 브라우저 캡처로 구간당 최소 2초~최대 3분; 정확히 60개의 개별 프레임을 매초 기록한다는 보장은 없습니다.
- PNG: 구간당 최대 200초(12,000프레임); ZIP 4GB 제한. 최신 크롬/엣지의 File System Access API가 지원되면 파일을 직접 디스크에 스트리밍합니다.
- Chrome/Edge의 저장 파일 선택 기능이 없는 환경: PNG ZIP 메모리 보호를 위해 최대 10초. 일반 웹 브라우저에서는 처리 시간과 사용 가능한 RAM에 제약이 있습니다.
- 장시간 라이딩은 **구간별로 짧게 잘라서 출력**하는 것을 권장합니다.

### Premiere Pro / DaVinci Resolve 사용
- WebM 투명: 해당 프로그램 및 코덱이 알파를 지원하는지 실제 내보낸 파일로 확인해야 합니다. 배경이 검은색이면 PNG 시퀀스를 쓰세요.
- WebM 초록: 크로마키/키어를 적용해 #00FF00을 투명하게 제거하세요.
- PNG: 압축 해제 후 `frames/frame_000000.png`부터 **이미지 시퀀스**로 가져와 클립 프레임레이트를 **60fps**로 설정하세요. 편집기에서 위쪽 비디오 트랙에 올려야 계기판만 합성됩니다.

## 개발자 테스트
- 별도 패키지 설치 없음. ES Module 자바스크립트 기반.
- 빠른 로컬 테스트: 이 폴더에서 `python -m http.server 8080`, 브라우저에서 `http://localhost:8080`.
- `tests/test.mjs` 는 Node.js 20+에서 `node tests/test.mjs`.
- Python v0.2 레이아웃 JSON의 `items`도 가져올 수 있습니다.

## 중요한 제한
현재 MVP는 FIT 필드 중 표준 `record` 메시지를 분석하는 구조이며 Garmin의 모든 제조사/확장/개발자 필드를 해석하는 범용 FIT SDK는 아닙니다. 실사용 Edge 1050 FIT 파일과 영상 편집기에서 검증해야 합니다. 실제 동영상 촬영 시작 시각을 읽어서 자동으로 동기화하는 기능은 아직 없고, FIT 구간을 사용자가 지정합니다. 영상 변환 및 서버 업로드 기능도 없습니다.

**개인 정보:** FIT에는 정확한 라이딩 시간과 이동 경로가 포함될 수 있으므로 공개 GitHub 저장소에 실제 FIT 파일을 업로드하지 마세요. 예제는 합성 데이터입니다.
